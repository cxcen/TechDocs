# 排列论证

排列论证用于证明两个列表包含相同的元素，但顺序可能不同。例如，`[2,3,1]` 是 `[1,2,3]` 的一个排列，反之亦然。

排列论证可以用来证明一个列表是另一个列表排序后的版本。也就是说，如果列表 B 与列表 A 包含相同元素，并且 B 中的元素已经有序，就可以确认，证明者对 A 进行了正确排序。

要判断两个列表是否相同，通常会先对它们排序，再逐元素比较。

然而，要确认一个列表已经排序，需要检查：1）元素顺序正确；2）排序算法的输出与输入包含相同元素。

这会产生循环依赖——要确认一个列表是另一个列表的排列，必须知道二者排序后的版本相同；但要确认排序算法执行正确，又必须知道排序输出是输入的一个排列。

这在普通代码中不是问题，但在 ZK 中，必须约束计算的每一步。

前面已经介绍过如何证明列表有序。本章重点讨论如何证明两个列表互为排列。

## 方案 1：为排序算法编写约束

前面一章介绍了如何为选择排序算法编写约束。选择排序算法的运行时间为 $\mathcal{O}(n^2)$，因此会产生 $\mathcal{O}(n^2)$ 个约束。可以使用归并排序等更高效的算法，以 $\mathcal{O}(n \log n)$ 个约束实现相同目标，但很快会看到，还有更好的方案。

## 方案 2：尝试直接约束一一映射

可以尝试直接编写一个电路，使其当且仅当一个列表是另一个列表的排列时才能满足。换句话说，第一个列表中的每个元素在另一个列表中都有匹配元素，反之亦然。

例如，要证明 `[a1, a2, a3]` 是 `[b1, b2, b3]` 的一个排列，就需要展示二者之间的映射。只需证明每个 `a_i` 都映射到列表 `b` 中的*某个*元素，并且每个 `b_i` 都映射到列表 `a` 中的*某个*元素。

为了创建证明双向映射的电路，我们定义一个由 `s` 信号组成的矩阵：

```

               b1             b2             b3
    --------------------------------------------
a1 | s11 = (a1-b1)  s12 = (a1-b2)  s12 = (a1-b3)
a2 | s21 = (a2-b1)  s22 = (a2-b2)  s23 = (a2-b3)
a3 | s31 = (a3-b1)  s32 = (a3-b2)  s33 = (a3-b3)
```

请注意，如果某个 `s` 信号为 0，对应的 `a` 元素与 `b` 元素就相等。例如，如果 `a3 == b1`，那么 `s31` 将为 `0`。

然后，分别按行和按列将 `s` 信号相乘，并像下图一样把乘积约束为 `o` 信号。只要存在至少一个匹配元素，对应的 `o` 信号就会为零。

```
     b1      b2      b3
a1  s11  ×  s12  ×  s13   =  o_row1
     ×       ×       ×
a2  s21  ×  s22  ×  s23   =  o_row2
     ×       ×       ×
a3  s31  ×  s32  ×  s33   =  o_row3
    ||      ||       ||
    o_col1  o_col2   o_col3
```

如果约束每个 `o` 信号都为零，就同时约束了 a 中的每个元素在 b 中至少有一个匹配元素，反之亦然。可以这样理解这些输出信号：

- `o_row1` 当且仅当 `a1` 与 `b` 中的某个元素匹配时为零。
- `o_row2` 当且仅当 `a2` 与 `b` 中的某个元素匹配时为零。
- `o_row3` 当且仅当 `a3` 与 `b` 中的某个元素匹配时为零。
- `o_col1` 当且仅当 `b1` 与 `a` 中的某个元素匹配时为零。
- `o_col2` 当且仅当 `b2` 与 `a` 中的某个元素匹配时为零。
- `o_col3` 当且仅当 `b3` 与 `a` 中的某个元素匹配时为零。

因此，如果所有 `o` 信号都为零，每个列表中的每个元素在另一个列表中都有匹配元素。

这种方法的缺点是，约束数量会随列表长度呈二次增长。

下面改为介绍一种用线性于列表长度的时间证明两个列表互为排列的方法。

**致谢：**本文余下内容大量参考了 [Triton VM 文档](https://triton-vm.org/spec/permutation-argument.html)，这里只是给出 Circom 实现，并增加了一些更适合初学者的解释。

## 排列论证的工作原理

考虑以下形式的多项式：

$$
(x-a)(x-b)(x-c)
$$

改变相乘顺序不会改变它的值：

$$
(x-b)(x-a)(x-c)
$$

换句话说，改变多项式[*一次因子*](https://www.notion.so/The-Permutation-Argument-14709cb3e96280489504de20d5f93804?pvs=21)的相乘顺序，不会改变多项式的值。（一次因子是形如 $(x - a)$ 的项。）

我们不会通过代数展开这些项来检查多项式是否相等，而是使用一种效率高得多的多项式相等性检验，即 [Schwartz-Zippel 引理](https://www.rareskills.io/post/schwartz-zippel-lemma)。

这项检验会随机采样一个 $x$ 值，并将其代入两个多项式。如果二者求值结果相同，那么它们以极高概率是同一个多项式（要了解这项检验为何安全，请参阅上面链接的文章）。

这项技术可以证明数组 $[a,b,c]$ 和 $[b,c,a]$ 互为排列。我们创建一个电路，以两个数组 $c_1,c_2,c_3,...,c_n$ 和 $d_1,d_2,d_3,...,d_n$ 作为输入，再构造多项式：

$$
\begin{align*}
(x - c_1)(x - c_2)...(x - c_n)\\
(x - d_1)(x - d_2)...(x - d_n)
\end{align*}
$$

最后，为 $x$ 选取一个随机点，对两个多项式求值，并约束二者的乘积相同。

为了生成随机点（称为 $r$），我们使用输入的哈希，也就是对两个数组拼接后的结果进行哈希：

$$
r=\mathsf{hash}([a,b,c,b,c,a])
$$

这样，证明者就无法选取一个使两个多项式相交的 $r$ 值来“作弊”。证明者提供多项式后，便无法控制这些多项式的求值点 $r$。

如果证明者更改多项式，检验它们的 $r$ 值也会改变。

下面的电路接收两个列表，并检查它们是否互为排列。数组信号 `prodA` 保存以下各项：

- $\texttt{prodA[0] = } r - a_0$
- $\texttt{prodA[1] = prodA[0]} \cdot(r - a_1)$
- $\texttt{prodA[2] = prodA[1]} \cdot(r - a_2)$
- $\texttt{prodA[n - 1] = prodA[n - 2]}\cdot(r -a_{n-1})$

因此，最后一项 `prodA[n - 1]` 保存多项式在 `r` 处的求值结果。这里的 `r` 是 `hash.out`，也就是数组 `a` 和 `b` 所有元素的 Poseidon 哈希。

```jsx

include "circomlib/poseidon.circom";

template IsPermutation(n) {
  signal input a[n];
  signal input b[n];

  // the random point will be the hash
  // of the concatenation of the arrays
  component hash = Poseidon(2 * n);
  for (var i = 0; i < n; i++) {
    hash.inputs[i] <== a[i];
    hash.inputs[i + n] <== b[i];
  }

  signal prodA[n];
  signal prodB[n];

  prodA[0] <== hash.out - a[0];
  prodB[0] <== hash.out - b[0];

  for (var i = 1; i < n; i++) {
    prodA[i] <== (hash.out - a[i]) * prodA[i - 1];
    prodB[i] <== (hash.out - b[i]) * prodB[i - 1];
  }

  // the evaluation of the polynomials at r = hash.out
  prodA[n - 1] === prodB[n - 1];
}

component main = IsPermutation(3);

/* INPUT = {
  "a": [1,2,3,4,5,6],
  "b": [1,2,3,4,6,5]
}
*/
```

## 漏洞：没有对所有元素进行哈希

以这种方式生成随机点时，哈希必须依赖计算的所有输入。否则，恶意证明者可以保持哈希值不变，并不断调整输出数组中的值，直到找到多项式的一个交点。

## 关于安全性的说明

该算法依赖以下性质：两个不相等的多项式至多在 $d$ 个点相交，其中 $d$ 是两个多项式次数的最大值。如果有限域大小远大于 $d$，在实践中就可以认为：当 $p$ 与 $q$ 是不相等的多项式，且 $r$ 是随机点时，$p(r)\neq q(r)$。Circom 使用的有限域大小略大于 $2^{253}$。如果多项式次数为一百万，那么 $r$ 恰好是交点的概率约为 $2^{20}/2^{253}$，也就是 $1/2^{233}$，或 $10^{70}$ 次中约 $1$ 次。这几乎与宇宙中原子的数量处于同一数量级。

不过，如果使用非常小的有限域，比如只有约 31 位，那么对于随机 $r$，$p(r)=q(r), q \ne p$ 的概率就不可忽略。
